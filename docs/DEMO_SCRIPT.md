# Five-Minute Demo Script

## 0:00–0:35 — Problem and promise

Show the permanent SANDBOX / MOCK DATA banner. Explain that an international student needs a route that is affordable, on time, and safe—not just a chatbot answer.

## 0:35–1:15 — Understand

Enter “Send some money to my landlord.” Show the single clarification question. Then use the GBP 9,000 tuition example and point out extracted recipient-target amount, currencies, beneficiary, and deadline.

## 1:15–1:55 — Plan

Show the ordered plan before execution. Highlight beneficiary verification, policy check, user checkpoint, token minting, and sandbox execution. Explain that plan validation prevents a model from deleting or reordering guardrails.

## 1:55–2:45 — Compare and explain

Open Compare. Show cost, recipient amount, ETA and deadline status for six fictional providers. Point out the recommended feasible route and deterministic explanation. State that all monetary math is Decimal and all data is MOCK.

## 2:45–3:35 — Safe execution and attack

Show T3 typed approval and enter the exact phrase. Display the simulated PENDING receipt. In Attack Lab, run the injection invoice and changed-bank-details invoice; show BLOCKED rule IDs. Explain request-bound HMAC tokens and replay rejection.

## 3:35–4:15 — User control

Show Reject, the cancel window, and STOP AGENT. Cancel a small T2 transfer while pending. Open Audit Log and show the VERIFIED chain badge.

## 4:15–5:00 — Value and evidence

Open Value. Show savings versus the mock bank baseline, deadline risks avoided, time estimate, 22/22 scenarios, 100% curated attack block rate, 0% false-block rate, and intent benchmark. Close with the limitation: these are controlled mock results, not production claims.
